# Grid 热路径优化验证（2026-10-08）

基线为 `b87aeb7c391c7cf833cd3d6c148b2b081beb6881`。对照采用相同场景、
同一编译器的优化前后程序，结果保存在 `build/grid-optimization-20261008/`。
本次没有改变公开布局 API、输出字段、浮点取整或 Grid 放置语义。

## 已落实的优化

1. **结构失效范围**：自身样式继续失效自身结构；只有 `display`、`position`、
   `grid.row/column` 变化才额外失效直接父节点的放置。拓扑修改失效对应容器；
   更高祖先继续重算尺寸。借用宿主样式时保守失效编辑节点及其直接父节点。
2. **auto-repeat 双槽缓存**：保留最近两组输入对应的不可变结构；普通 Grid 只保留一组。
   实际的 Flex 内嵌 auto-fill 场景确认会交替使用内在尺寸与最终尺寸两个输入，
   预热后每次内容更新的结构重建从 2 次降为 0 次。
3. **轨道计算**：auto-fit 占用用差分数组在结构创建时计算并缓存；增长上限阶段只提交
   `touched` 轨道；跨轨道的 MaxContent 条件预先计算，避免重复扫描同一跨度。
4. **自动放置索引**：按次轴索引合并的主轴区间，并缓存每行最后自动放置位置。
   少于 64 项使用线性扫描；次轴跨度超过 64 的区域和查询保留紧凑回退；
   全部显式放置时不保存占用区域。索引临时内存通过 pmr arena 成批分配。
5. **Grid 工作区**：复用两轴轨道、条目贡献、跨度分配、排序、基线分组和片段数组。
   递归查询租借独立工作区，退出及异常时清空逻辑内容，保留容量供后续查询使用。
6. **浮动布局**：复用区域及空闲区间数组，增量维护 clear、最大底边和最大顶边。
   保留实际底边与占用底边的区别。

索引消除了常见查询对全部已放置区域的扫描，并未保证所有 Grid 输入都有线性复杂度。
dense 搜索、碎片区间插入和大跨度回退仍可能退化；浮动布局仍需扫描及排序相交区间。
未在本次改动中取消 `.at()` 检查、跳过隐藏子树深度检查、改写 `LayoutBox` 引用生命周期，
也未改动 `float_subtree_`、具名线字符串表示或树环检测。

- Debug 82/82；MSVC AddressSanitizer 82/82。
- 参考配置 137/137，其中 55 项为 Taffy/参考语料测试。该结果不表示完整 CSS 规范等价。

- 内存契约覆盖 Flex、Grid 和浮动 Block：树销毁后资源活跃字节归零；保留资源后可供新树复用。
  最后的该项扩展在上述构建中均重新运行通过。
- 两种输出模式各 31 组基准配置均通过四帧完整几何的逐位比较，包含所有节点矩形、
  盒模型、溢出、基线、轨道尺寸、位置和条目放置；计时阶段额外校验消费结果。

Clang 22.1.8 ASan 在 82 项中有 10 项异常路径失败，堆栈指向
`VCRUNTIME140.dll 14.51.36247.0`。从原始基线源码重新编译后，异常原子性、
宿主异常类型和缓存失败回滚三项也出现相同地址的运行库崩溃。
因此这部分不能标为通过，也没有为通过测试而屏蔽异常用例；本次内存检查的通过证据来自
MSVC ASan。基线复现日志为 `baseline-asan-recheck.log`，当前版本日志为 `../grid-asan.log`。

## 计时口径

- Windows x64，Intel i7-11700K；MSVC 19.51.36257.0，Release `/O2 /Ob2 /MD`，未启用 PGO/LTO。
- 系统电源方案为“平衡”；进程及子进程固定逻辑 CPU 4。计时串行运行，期间本任务没有并行编译或测试。
- 3 轮，每轮 7 批，每批 3 次；轮间反转旧版/新版顺序。dense 1,000/2,000 项因旧版耗时较长，
  每轮使用 3 批、每批 1 次。表中为各批平均耗时的中位数，单位为 µs。
- `cold` 从尚未布局的新树开始，建树及销毁不计时；其他模式每批先预热 4 次。
  `edit` 包括改样式，`content` 包括标脏，`resize` 包括改变约束。
- 完整输出使用 `publish_nodes=true, collect_grid_tracks=true`；精简输出关闭这两个选项。
  两种模式都计入布局后读取首、中、末三个根相对矩形的成本，分别运行，不能据两列差异推断输出成本。
- 分配计数、工作计数各自使用独立程序，其扰动后的时间不用于性能表。
  `peak_incremental_bytes` 只统计测量区间内新分配的峰值，排除预热保留的内存，不能当作整个进程或树的内存峰值。
- 工作区保留容量、auto-repeat 保留第二套结构，以活跃内存换取复用；空闲缓存上限不限制这部分活跃内存。
- 这是该机器上的合成场景结果。小于 1 µs 或几个百分点的差异不足以认定改进或回退；
  dense 是固定 16 列的退化压力输入，其大倍数不能外推到普通页面或整个应用。

## 重放方法与原始证据

先用 `./scripts/build-msvc.ps1 -Preset benchmark-release` 构建计时和分配程序。
修改前后分别保存 `axisly_css_grid_bench.exe` 与 `axisly_css_grid_allocations.exe`，
相同的 benchmark 源码必须用于两边。工作计数使用单独的构建目录；在已初始化 MSVC 的环境中：

```powershell
cmake -S . -B build/grid-metrics -G Ninja -DCMAKE_BUILD_TYPE=Release -DAXISLY_BUILD_TESTS=ON -DAXISLY_BUILD_BENCHMARKS=ON -DAXISLY_ENABLE_GRID_METRICS=ON
cmake --build build/grid-metrics
ctest --test-dir build/grid-metrics --output-on-failure
```

本机已保存的程序可直接重放：

```powershell
python benchmarks/grid_compare.py --baseline build/grid-optimization-20261008/baseline.exe --candidate build/grid-optimization-20261008/final.exe --allocation-baseline build/grid-optimization-20261008/baseline-allocations.exe --allocation-candidate build/grid-optimization-20261008/final-allocations.exe --metrics-baseline build/grid-optimization-20261008/baseline-metrics.exe --metrics-candidate build/grid-optimization-20261008/final-metrics.exe --output build/grid-replay --cpu 4 --full
```

去掉 `--full` 测精简输出。`--case` 可重复缩小场景；`--environment` 可传入记录工具链、
源码和机器条件的 JSON。进程亲和性复用现有三方基准的实现，不改变系统电源配置。

`final/` 与 `final-full/` 分别保存两种输出模式的 `samples.csv`、`summary.csv`、
`geometry.csv`、`manifest.json`；其中 P95 是批平均值的 P95，不是逐帧延迟 P95。
manifest 记录程序 SHA-256、参数及环境。目录内还保存原始基线源码、基线计数补丁、
基准源文件和最终源码快照，便于对照。所有生成结果均位于忽略的 `build/` 目录。
