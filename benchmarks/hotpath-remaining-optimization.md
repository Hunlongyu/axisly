# 剩余布局热点优化验证（2026-10-09）

本轮接续 [第一轮热点优化](hotpath-optimization.md)。比较基线是第一轮完成后的
工作区，不是原始提交；两轮加速比不能相乘。源码和公开 API 仍位于同一主工作区。
原始计时、分配、构建与测试记录在 `build/hotpaths-remaining-20261009/`。

## 剩余建议的处理

| 原建议 | 处理 | 正确性边界 |
| --- | --- | --- |
| 5. 借用节点查找 | 继续合并 Block 的重复父节点查找；未增加跨 epoch 子节点指针数组 | 现有 Flex 工作项已保存节点指针；通用数组还需逐 epoch 解析、额外存储及宿主地址失效处理，目前没有独立证据支持引入 |
| 6. 根节点头部插入 | 叶子数组首次分配时占用原本预留的根槽位，转移发布时直接填入 | 所有内部叶遍历跳过预留位，公开数组仍按根优先、深度优先排列 |
| 7. 隐藏子树中间结果 | 非 Full 查询只给当前请求生成根几何，后代仅遍历校验 | 仍访问宿主节点并验证深度；Full 查询仍包含全部隐藏节点 |
| 8. 批量子节点更新 | 祖先链只扫描一次；按旧父节点统一失效和移除；相同列表直接返回 | 校验及分配完成后再提交，支持父子同时迁移、列表别名、原顺序及分配失败恢复 |
| 9. 布局盒复制 | 根布局盒使用引用；Block 有 containing width 时引用原盒 | 无 containing width 时仍保留周期百分比解析的独立副本 |
| 10. Grid 报告选项 | 仅失效 Grid 容器及祖先，保留其他分支缓存 | 仍扫描全体节点元数据；共享祖先只失效一次；提供者或 revision 变化仍全部失效 |

第 10 项使用缓存的 Grid 分类与已有父链接，失效时不读取借用样式的旧地址，也不回调宿主。
字段与现有 Grid 布尔标志合并存储；整个失效过程不新增容器分配。
第 8 项复用重复/环检查的缓冲区收集旧父节点，迁移路径仍只申请两个临时数组。

## 测量方法

- Windows x64、Intel Core i7-11700K、MSVC 19.51.36257.0，Release `/O2 /Ob2 /MD`。
- 与第一轮相同的平衡电源方案；计时驱动与子进程固定 CPU 4，串行计时，构建和测试先结束。
- 优化前静态库单独保存，前后程序使用同一份最终 `css_hotpaths.cpp` 和相同编译选项。
- 3 轮 × 9 批，交换前后程序的执行顺序；比较消费校验和并保留全部批记录。
- 表中为批均值中位数，探索性 95% 区间跨 1 的项目标为不确定；低于 1 µs 不作倍数结论。
- 拓扑 API、报告切换与大树每批 64 次，普通 1,000 叶布局每批 128 次。
  Flex 首次布局出现回退信号后，另用 6 轮 × 9 批、每批 256 次单独复核。
- `batch_move` 在两个父节点之间迁移全部子节点；`deep_reorder` 在 32 层祖先下反转列表。
  两者仅计拓扑操作，不计建树或布局；计时前另外检查拓扑和重新布局的一致性。
- `tracks_*` 每次切换报告开关、不修改样式。混合场景为 16 组中的一组 Grid，其余为 Flex；
  借用版本使用相同结构。计时包括计算与三个节点查询。
- `hidden` 在 16 个可见 Block 中放置隐藏子树，外层 Flex 使用基线对齐。
  其他布局场景沿用第一轮设置；最多 100 叶的同结构场景在计时前比较所有几何字段。

## 已确认的针对性收益

| 场景 | 数量 | 优化前 → 后（µs） | 加速比 |
| --- | ---: | ---: | ---: |
| 批量迁移 | 1,000 子节点 | 199.34 → 23.90 | 8.34× |
| 批量迁移 | 10,000 子节点 | 17,758.34 → 555.59 | 31.96× |
| 深层重排 | 1,000 子节点 | 375.96 → 35.29 | 10.65× |
| 混合树切换 Grid 报告 | 1,000 叶节点 | 682.27 → 98.40 | 6.93× |
| 借用混合树切换 Grid 报告 | 1,000 叶节点 | 939.64 → 129.24 | 7.27× |

这些场景的区间均支持提速。报告开关保持不变的普通帧没有第 10 项的收益。
完整规模和不确定结果见 `mutations/summary.csv`、`diagnostics/summary.csv`、
`layout/summary.csv` 和 `flat-large/summary.csv`。

| 取整按需发布、首次布局 | 1,000 | 972.76 → 924.42 | 探索区间支持提速 |
| 隐藏子树、首次布局 | 1,000 | 333.78 → 422.63 | 不确定 |
| 隐藏子树、单叶修改 | 1,000 | 36.71 → 26.32 | 不确定 |
| 大扁平树、单叶修改 | 10,000 | 13,478.80 → 11,410.38 | 不确定 |
| 隐藏子树、单叶修改 | 10,000 | 2,009.07 → 1,837.03 | 不确定 |

Flex 基线场景首次布局初测为 1,077.85 → 1,305.46 µs，区间支持回退；
较大批次复核为 1,871.13 → 1,583.49 µs，方向反转，区间上限接近 1。
两次记录均保留，复核在 `baseline-recheck/`；这一项不作稳定快慢结论。
第 6、7、9 项确实减少了搬移、临时几何构造和值复制，但本轮未分别隔离其耗时贡献，
也没有把全部场景中位数下降都计为已确认加速。

## 分配与工作量

分配探针单独运行，计时完成后采集；其时间不作为速度结论。
`allocations.csv` 保存 126 条记录，下面是每次操作的平均值，均为 1,000 叶/子节点。

| 场景 | 分配次数（前 → 后） | 申请字节（前 → 后） | 布局查询次数（前 → 后） |
| --- | ---: | ---: | ---: |
| 批量迁移 | 2 → 2 | 16,078 → 16,078 | 不包含布局 |
| 相同子节点列表重复提交 | 2 → 0 | 16,078 → 0 | 不包含布局 |
| 混合树切换报告 | 56 → 11 | 154,340 → 14,387 | 4,758 → 902 |
| 借用混合树切换报告 | 56 → 11 | 154,340 → 14,387 | 4,758 → 902 |
| 无 Grid 的 Flex 树切换报告 | 49 → 2 | 152,184 → 2,832 | 4,065 → 17 |

其余查询、Block、取整、基线、隐藏场景的分配次数和申请字节均与本轮基线一致。
因此根槽位与打包的 Grid 标志在这些场景中没有新增分配容量；隐藏查询省去的是池对象
构造和释放，不是逐节点堆分配。申请字节不是进程驻留内存。
