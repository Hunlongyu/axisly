# M5 跨行、跨列与尺寸贡献

本文记录 M5 的 `0.0.6` 验收快照：实现 `column_span` 和 `row_span`，支持固定／Content／权重轨道上的跨格矩形、尺寸贡献、对齐和宽度约束测量。跨度逻辑集中在 `src/detail/span_resolution.hpp/.cpp`，公共 `Track` 值不被修改。当前 Range 上限与跨格重新分配规则见 [M6 文档](14-range-layout.md)。

## 放置与几何

span 表示轨道数量，默认 1，必须大于零并落在显式网格内。放置校验先检查索引，再以 `span <= count - start` 判断边界，避免无符号加法溢出。零跨度、越界跨度和不能容纳的最大整数返回 `InvalidSpan`，保留条目 ID。所有条目先验证，再调用宿主测量。

合并区域从第一条轨道的起点开始，长度为所跨轨道尺寸之和加内部 gap。不包含区域外的 gap 或 padding。`cell_rect` 保存这个完整区域，随后只应用一次条目 margin 和对齐，得到 `rect`。

例如列宽 `40、60`、列间 gap=10，跨两列的宽度为 110。两条零宽轨道之间若有 gap=5，跨格区域宽度仍为 5。

不同 ID 可以覆盖相同或重叠的区域；算法不执行避让或自动放置，输出顺序仍与输入顺序一致。重复 ID 继续报错。

## 尺寸贡献顺序

每个轴独立执行以下流程：

1. 收集单格 Content 的最小和首选尺寸，保留 M4 行为。固定轨道以固定值开始，权重轨道以显式数值 minimum 开始。
2. 处理所有跨格条目的 minimum，按跨度从短到长分组。
3. 使各轨道的 preferred 不小于处理后的 minimum，再按同样顺序处理跨格 preferred。
4. 将计算出的轨道约束交给既有 Content 收缩和权重空间分配器。

条目在该轴的要求为 `测量尺寸 + 两侧 margin`。计算缺口时，先减去跨度内各轨道已有尺寸和内部 gap。

| 跨格情况 | minimum 缺口 | preferred 缺口 |
| --- | --- | --- |
| 包含 Content | 缺口在这些 Content 之间均分 | 缺口在这些 Content 之间均分 |
| 没有 Content，包含 Weighted | 按权重补足，遵守各自 maximum | 保留由容器空间决定的权重分配 |
| 全部是 Fixed | 保留固定尺寸 | 保留固定尺寸 |

Content 分配的是扣除已有占用后的缺口。固定轨道不参与增长；跨度之外的轨道不接收该条目的贡献。

minimum 补足过程可能提高权重轨道在本次计算中的下限，但不会改动 `Track::definition()`，也不会超过显式 maximum。已经达到上限的轨道冻结，未满足的增量交给跨度内其余可增长的权重轨道。每轮重新统计活动权重，避免极大权重被移除后丢失很小的剩余权重。

minimum 的缺口按权重分配的是增量；之后容器剩余空间仍按 M2 的总尺寸比例规则分配，并受提高后的下限限制。preferred 不会被转换为权重轨道的硬下限。

单格 Fixed／Weighted 的测量保持 M4 行为，不自动增加轨道下限。M5 新增的权重下限补足仅针对该轴 span > 1 的条目。

## 重叠跨度与顺序

同一跨度组使用组开始时的尺寸快照。每个条目独立计算需要的增量，每条轨道采用这一组所有计划增量的最大值，组末统一应用；不会按条目依次累加。

因此，对于返回相同度量的宿主回调，调整条目输入顺序只改变输出排列，不改变条目几何。同一跨度、相同区域上的多个条目采用最大需求，避免重复扩展。较长跨度会看到较短跨度已经产生的增长。

例如三条初始为零的 Content，两个条目分别跨第 1～2 列、第 2～3 列，各要求 minimum=100。两者都计划让覆盖的两列各增加 50；合并后为 `50、50、50`，两个跨度都得到 100。重叠约束可能扩大整体占用，这套规则不求所有跨度约束下的最小总宽度。

## 分配示例

以下表格均不含 padding；除明确注明外，gap 为零：

| 轨道与条目要求 | 结果 |
| --- | --- |
| Fixed=80、Content，gap=10，跨两列 preferred=200 | 列宽 80、110 |
| 两列单格 preferred=80、20，gap=10，跨两列 preferred=200 | 缺口 90，各增 45，列宽 125、65 |
| Weighted 权重 1:2:3，跨三列 minimum=120，容器宽度 0 | 下限为 20、40、60，网格溢出容器 |
| 上例容器宽度变为 300 | 列宽 50、100、150 |
| Weighted 权重 1:3，已有 minimum=60、0，跨两列 minimum=100 | 增量为 10、30，计算下限为 70、30 |
| Weighted 权重 1:3，第一个 maximum=30，跨两列 minimum=200 | 第一个冻结为 30，第二个得到 170 |
| Weighted maximum 分别为 30、70，跨两列 minimum=200 | 保留 30、70，条目裁剪到实际区域 |

当固定尺寸或所有权重上限使要求无法满足时，仍返回合法布局，条目按实际区域裁剪。这延续 M3／M4 对无法容纳内容的处理。Content 和可满足的权重 minimum 则会在空间不足时使网格溢出容器。

## 两阶段测量与对齐

第一次测量的宽度用于单格／跨格列贡献。列分配结束后，组合跨列区域，再应用 margin、横向对齐和首选宽度裁剪，把最终条目宽度传入第二次测量。第二次返回的高度用于单格／跨格行贡献。

例如固定列 `70、70`、gap=10，跨列文字固有度量 `400×20`，第二次会以宽度 150 测量，得到 `150×60`。如果同时跨两条 Content 行且 row_gap=10，行高各为 25，完整区域高 60。

横向非 Stretch 的条目可能比合并区域更窄，传入的是最终 `rect.width`。第二次返回的宽度不再修改列；known_height 保持未知。Span 不增加测量轮数，有回调的成功布局仍为每个条目两次调用。

Start／Center／End／Stretch 与超大 margin 的行为沿用 M3，仅将原单元格换成合并区域。测量错误、异常传播、输入不变性及 `measurement_count` 的约定沿用 M4。

## 数值处理

跨度尺寸通过累加内部轨道尺寸和 gap 得到，使用 double 中间值。不会以两个大坐标相减来求跨度宽高，避免极大坐标处的小区域尺寸被抵消。跨度为 1 时直接使用原轨道结果，保留已有计算路径的精度。

轨道最小总占用无法表示为有限 Unit 时，返回 `NumericOverflow`，零 size、空 items，保留已经调用的测量次数。超大 preferred 若能通过 Content 收缩得到有限结果仍可成功。最终输出依旧是 float；没有像素舍入功能。
