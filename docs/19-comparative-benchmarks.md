# 19 — gridly／Taffy／Yoga 同场景性能对比

本页保存 `0.0.11` 的历史基线；`0.0.12` 已新增可选 `GridCache`，缓存后的同场景重测见 [完整布局缓存](20-layout-cache.md)。下面的历史数据保持不变，当前比较工具会额外运行 `gridly_cached`。

2026-09-28 本机实测，比较 gridly `0.0.11`、Taffy `0.14.0` 和 Yoga `3.2.1`。在本轮显式、平面、空间充足的场景中，gridly 首次计算和连续缩放更快；输入不变的重复调用则由 Taffy／Yoga 的缓存明显占优。这里没有覆盖全部 CSS、嵌套 UI、真实字体排版或渲染耗时。

## 先确认是同一个布局任务

共 11 个场景：6 个单轴场景三库比较，5 个 Grid 场景比较 gridly／Taffy。Taffy 全部使用 Grid 算法；Yoga 在单轴场景使用 Flexbox，对跨格和二维 Grid 标为不适用，不用多层 Flexbox 替代后混报。

三者读取同一份文本 fixture，条目数量、顺序、固定尺寸、权重、padding、gap、测量度量和容器变化序列相同。统一左到右方向、无 margin、无边框、关闭像素取整。三者都保持单层布局：N 个条目，Taffy／Yoga 另有 1 个容器节点；gridly 容器由 `GridSpec` 表示。

每场景有 17 种容器尺寸。计时前同时检查复用树和每次新建树的结果，共 28 个“引擎×场景”组合、952 组布局、1,319,200 个条目矩形。所有 x/y/width/height 均与独立解析计算结果相等，实际最大绝对误差为 0；准入阈值为 `1e-4 + 1e-6 * max(abs(a), abs(b))`。若数量、几何或计时期间的结果校验值不符，程序立即失败，不生成成功排名。

比较的是实际条目矩形。gridly 的 `result.size` 是轨道占用范围，另两库根节点是容器盒子，两者定义不同，因此不混作同一个比较量。工具没有 M8 的探针节点，也不把进程启动、JSON 或 Python 耗时算作布局耗时。

## 计时定义

| 模式 | 每次调用前的状态 | 计时内容 |
| --- | --- | --- |
| `cold` 首次布局 | 新建、未计算过的树／输入适配器 | 公共布局 API，加首／中／末三个矩形的结果消费 |
| `resize` 连续缩放 | 复用树，先在末帧预热，再循环 17 个不同容器尺寸 | 同上，允许引擎正常复用有效缓存 |
| `same` 输入不变 | 复用已计算的树，尺寸也不变 | 同上，观察重复调用的缓存行为 |

`cold` 和 `resize` 使用相同的尺寸序列。`cold` 指每棵树的首次布局，不是冷启动进程或清空 CPU 缓存；代码路径均已预热。建树／构造输入、旧结果释放和树销毁在所有模式中都放在计时之外。因此这是**布局调用成本**，不是“创建控件到渲染”的端到端成本。

gridly 的输入校验、内部临时分配、输出矩形数组生成在 API 内，会被计时。Taffy／Yoga 将结果保留在节点上，计时后也不额外提取完整数组。各 API 固有的数据所有权不同，不能把结果理解为移除 API 成本后的纯算法内核速度。

两轮串行执行，第二轮交换引擎顺序；每轮 9 批。≤1,000 条目的场景每批 340 次，其余每批 34 次，均为 17 帧的整倍数。C++ 用 `steady_clock`，Rust 用 `Instant`，在各自进程内部逐次计时，再求批均值。下表是两轮共 18 个批均值的中位数，未挑选最快一轮。P95、各轮中位数范围、每批数据均保存在原始报告中。

## 内容测量次数

`row_content_100` 使用 100 个固定固有宽度、固定高度的模拟内容条目，单次度量只返回尺寸，不做真实字体排版。其他场景不设置内容测量回调。

| 模式 | gridly | Taffy | Yoga |
| --- | ---: | ---: | ---: |
| 首次布局 | 200 | 300 | 100 |
| 连续缩放 | 200 | 0 | 0 |
| 输入不变 | 200 | 0 | 0 |

缩放时 Taffy／Yoga 可以沿用有效的内容测量；gridly 仍执行两轮测量。真实字体测量可能远比这个算术回调昂贵，本轮速度关系不能外推到文本密集界面。

## 机器、版本和结果边界

- Windows 11 x64 10.0.26200，Intel i7-11700K，8 核／16 线程。单线程，未固定 CPU 亲和性；计时期间未并行构建或跑其他基准，普通桌面活动仍可能引入波动。
- gridly／Yoga：MSVC 19.51.36257，Release `/O2 /Ob2 /DNDEBUG`，无 LTO。Yoga 保留上游异常处理／禁用 RTTI 等设置，另外指定 `/utf-8`，不修改其算法。
- Taffy：Rust 1.98.0，`opt-level=3`、`lto=false`、`codegen-units=16`，仅启用 `std`、`taffy_tree`、`grid`；依赖由 Cargo.lock 固定。
- 场景使用递增 ID、显式放置和足够空间，无溢出／收缩、复杂 Range、乱序 ID、嵌套、自动放置、百分比轨道或真实文本。千条单轴场景采用长画布，不代表一般窗口尺寸；根节点的 100% 宽高仅用于映射共同的外部容器尺寸。
- 本轮比较耗时和测量次数，没有测三库的内存分配、进程内存或建树成本。此前 [gridly 自身基准](18-performance-benchmarks.md) 还包含结果析构，不能把那一表数值直接拼接到本报告。
- 场景的规模和内容是共同子集，不能据此宣称 gridly 替代了完整 CSS Grid／Flexbox，或在所有真实 UI 中更快。

## 复现

比较工具默认关闭，只在专用预设中启用。Windows PowerShell：

```powershell
./scripts/build-msvc.ps1 -Preset comparison-release
python benchmarks/comparison/compare.py `
  --native build/comparison-release/gridly_comparison_native.exe `
  --taffy build/comparison-release/benchmarks/comparison/cargo/x86_64-pc-windows-msvc/release/gridly-taffy-bench.exe `
  --output build/comparison-results
```

首次需要网络下载 [Yoga 3.2.1](https://github.com/facebook/yoga/releases/tag/v3.2.1) 和 Cargo 锁定的依赖；Yoga 归档有 SHA-256 校验。其静态库只链接到比较程序，生产 `gridly::gridly` 不链接它。其他平台可用 `cmake --preset comparison-release` 及对应 build/test 预设；Rust 输出路径的目标三元组需改为本机 `rustc -vV` 显示的 host。

`--smoke` 保留全量几何检查，计时缩短为 2 次×2 批，仅用于工具正确性检查。缓存调用可能短于时钟分辨率，冒烟允许零耗时；正式运行要求正的批均值。`--samples`、`--rounds` 可调整正式采样，不应混合不同配置作历史比较。

构建后比较程序的 Yoga 许可保存在 `comparison-yoga-LICENSE.txt`。不安装比较程序、Yoga 或 Rust 目标。完整 Release 构建测试 214/214 通过；安装消费工程和默认子目录消费工程各 1/1 通过。错误矩形、NaN 和缺失条目均验证为拒绝。计时测试没有速度阈值，本机结果不代表已经完成其他平台实测。
