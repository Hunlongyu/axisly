# 21 — 工作区复用与预处理缓存

`0.0.13` 优化重新布局所需的内存和重复预处理。`compute_grid` 仍无状态，`GridCache` 的输入快照、失效接口、借用结果和测量契约保持不变。

## 实现范围

- 跨格增长算法复用候选数组，不再为每个跨度／增长阶段创建临时 vector。首次遇到跨格时按实际跨度条目数一次预留记录空间，避免反复扩容搬移；纯单格输入不会执行这次计数或分配跨度数组。
- 固定轴直接计算轨道位置，省去不会改变固定尺寸的内容贡献和跨格排序。测量回调仍完整执行，条目对齐继续使用测量结果。
- 每个 `GridCache` 保留独立的 ID 校验、测量、轨道、跨格、结果缓冲区；工作区容量足够时，缓存未命中也无需分配新内存。
- 无状态 `compute_grid` 在校验／各轴计算完成后及时释放已用完的临时缓冲区，降低一次性调用的峰值内存。
- 缓存已校验的静态输入和跨度顺序；仅尺寸、内容版本、测量绑定或显式失效发生变化时，复用这些预处理。修改 spec 或任意条目后重新校验和准备。

每次未命中都清空动态尺寸贡献，并重新执行测量及数值检查。内容变小不会沿用上次增长，失败后不会泄漏旧矩形。容器错误仍优先于输入错误；成功且绑定回调的布局仍测量 `2 × 条目数` 次。没有新增条目级测量缓存、局部重排或 dirty 树，也没有引入共享／线程局部工作区或第三方依赖。

## 内存与生命周期

复用通过保留容量换取减少分配。缩小网格、`invalidate()` 和布局错误不会主动归还工作区／结果的容量，销毁 `GridCache` 时释放。增大条目、轨道或跨度集合可能再次分配；`set_spec`／`set_items` 的输入快照复制仍可分配，不应每帧提交全量输入。

分配探针只统计当前线程的 C++ `new/delete`，不表示进程 RSS、分配器内部占用或第三方引擎内存。预热保留字节包含布局调用中新建并仍存活的输出／工作区，不包含此前构造的缓存对象和输入快照。后续调用的 `retained_bytes=0` 表示探针窗口内没有新增保留分配，不表示缓存不再占用内存。

2026-09-28 无状态分配复测如下；为验证确定性分配次数使用 `--smoke`（3 批×2 次），计数程序不提供性能耗时结论。与正式竞品比较使用不同的 gridly 专用场景。

| 场景 | 每次分配：前 → 后 | 每次申请字节：前 → 后 | 峰值存活字节：前 → 后 |
|---|---:|---:|---:|
| 100×100 Weighted | 36 → 12 | 935,590 → 904,312 | 732,995 → 723,317 |
| 50×50 Content／Range 密集跨格 | 4,094 → 17 | 1,153,642 → 426,914 | 277,596 → 183,037 |
| 100×100 Content／Range 密集跨格 | 16,505 → 17 | 4,177,474 → 1,693,431 | 978,794 → 725,876 |

无状态调用按阶段释放临时缓冲区，以上场景的分配次数、累计申请量和峰值存活字节均下降。`GridCache` 则保留双轴工作区供下一帧复用：缓存专用 10,000 条目用例在预热后保留约 0.86 MiB（Weighted）或 1.62 MiB（混合跨格）的输出／工作区，超过仅保留布局结果的旧版本。减少分配不等于降低缓存实例的常驻内存。

缓存探针分别对 400／10,000 条目的 Weighted 和混合跨格执行缩放、内容版本变化、显式失效、同容量单条目更新，每种 64 次，全部零分配，并逐帧与无状态完整结果比较。混合跨格的每次测量仍为 800／20,000 次；输入不变的 8 组命中测试各执行 1,000 次，均零分配、零测量。

## 比较方法

先保留 `0.0.12` 可执行文件，再修改核心并编译 `0.0.13`。两者使用同一比较工具：重复布局时旧输出的释放计入计时，适配器构造、输入快照、最终析构不计时。旧的 0.0.12 报告将无状态路径的旧输出释放放在计时外，因此这里重新采集优化前数据，不直接拼接历史耗时。

共同输入包含 11 个场景、17 个容器尺寸。先逐一检查全部矩形，再计时首次布局（cold）、连续缩放（resize）和相同输入（same）。Yoga 仅参与能映射为单轴 Flexbox 的 6 个场景。比较中的跨格场景为无测量的 Fixed／Weighted；另有 gridly 专用 Content／Range 密集跨格场景用于分配验证，二者不能混称同一测试。

正式计时为 2 轮，每轮 9 批；每批小场景 340 次、大场景 34 次，第二轮反转引擎顺序。Windows 11 x64，Intel i7-11700K，MSVC 19.51.36257 Release `/O2 /Ob2 /DNDEBUG`；Taffy 0.14.0 使用 Rust 1.98.0 opt-level=3；Yoga 3.2.1。均未启用 LTO，未固定 CPU 亲和性。正式计时没有并行构建或其他基准。表中为批均值的中位数，单位 µs／次，不是单次调用尾延迟；不足 1 µs 的缓存命中不作纳秒级排名。
