# 当前 CSS LayoutTree／Taffy／Yoga 三方基准

2026-09-30，本机 Release 实测。生产源码为 `711317a`；新执行器调用
`axisly::css::LayoutTree`。Taffy 固定 0.14.0，Yoga 固定 3.2.1。
本报告的输入和 API 与早期 `compute_grid` 共同子集不同，分别保留历史数据。

## 结果

- 18 个场景；155 组引擎／模式几何重放通过，4 组本库深树资源上限单列；
  两轮共 310 条计时记录，每条有 9 批数据。
- 平面 Flex 首次耗时约为 Taffy 的 7.6–9.5 倍；嵌套文本约为 15.6–17.4 倍。
  弹性 Grid 首次约为 Taffy 的 3.6–3.8 倍，固定 Grid 约为 9.9 倍。
- 局部更新能复用未变子树。384 叶嵌套文本本库约 356 µs，Taffy 约 13 µs，
  Yoga 约 463 µs；本库快于此输入中的 Yoga，仍有明显的 Taffy 差距。
- 输入不变时三库均零测量、耗时低于 1 µs。数字接近时钟和包装调用开销，
  不据此给缓存路径排纳秒级名次。
- 本库 12 层内容驱动深树在默认预算下无法发布结果，须作为性能与稳定性问题跟进。

## 深树失败与后续优先级

失败输入是 [flex_deep_12.txt](fixtures/flex_deep_12.txt)：13 个竖向 Flex 容器、
16 个测量叶子，共 29 节点。尺寸由内容驱动，随可用宽度改变文本行数。
层数低于默认最大深度 64。默认测量预算是每次 compute 100,000。

首次窄视口返回 `LimitExceeded`，报告 `measurement_count=100001`、
`layout_count=429882`；其余三个模式在预热时返回同类错误，布局计数为 477172。
计数超限的一次尝试未调用宿主测量。Taffy／Yoga 可以完成：首次约 36／44 µs，
测量回调分别为 80／16 次。本轮没有提高预算，也没有给失败项填耗时名次。
[全部失败记录](failures.json)与原输入保留。

需要优先剖析深层固有尺寸传播、查询缓存及探测复用；随后定位正常 Flex 首次布局的
分配和输出存储开销。字段/API 覆盖与原有 6020 项差分验收已经完成，
本次新增深树输入揭示了原验收范围之外的实际限制。

## 校验与计时

每个正式计时输入帧，先在计时外输出全部节点的根坐标 x/y/width/height，与
Taffy 对照；cold 每帧新树，其他模式复用树。通过的路径共重放 5,293,494 个节点矩形
（含参考端），最大绝对误差为 0.000757227 像素。
容差采用既有全量差分的 0.01px 绝对下限，加 1e-6 相对项。
初始更严格容差在收缩累加中遇到约 0.0005px 的浮点差，正式结果全部小于 0.001px。
独立比例收缩公式在 533px 视口的第 76 个子项给出 x=398.75，Taffy 为约 398.7495。
所有计时批次另校验首／中／末节点 checksum 以及测量次数稳定性。

- 两轮串行；第二轮逆转引擎顺序，每轮 9 批。≤129 节点每批 170 次，其余 34 次，
  均为 17 个视口的整倍数。P95 是批均值的百分位，并非单帧 P95。
- C++ `steady_clock`、Rust `Instant`，进程内部计时。解析、建树、预热、全部几何导出、
  进程启动和最终销毁不计时；编辑/失效、公开 compute 及三个矩形消费计时。
- 使用各库的原生输出所有权：本库发布根坐标数组和 Grid 诊断，Taffy／Yoga 将结果
  保存在节点。后两者三个坐标读取包含向父节点累加；不额外导出完整数组。
- Taffy 启用全部布局算法、balance、calc、content_size 和 detailed_layout_info，
  与本库 Grid 诊断的计算范围一致。没有启用字符串解析。
- 测量使用相同的算术度量，包含宽度约束下的模拟换行；没有测真实字体、绘制或
  窗口呈现，没有采集三库内存分配和进程内存。
- i7-11700K，8 核／16 线程；Windows 11 x64；MSVC 19.51 Release `/O2 /Ob2 /DNDEBUG`；
  Rust 1.98.0 `opt-level=3`。两者没有 LTO。未绑 CPU，普通桌面活动可能引入波动。
  部分平面组两轮中位值有 15% 以上差异，范围与 P95 均保存，不将单个数当作保证。
- 本轮没有改变生产布局算法。比较预设构建与 CTest **332/332** 通过；该 smoke 门禁
  覆盖 7 个代表场景。完整 18 场景运行额外记录了上述 4 个深树资源上限组。

默认不带 `--record-limits` 时遇到预算错误立即失败。此选项只接受公开 API 返回的
资源上限错误，保留失败输入/原因，并跳过该引擎/模式的计时；几何不符、异常退出、
checksum 不符或计数不稳定仍会立即失败。`--smoke` 仅用于工具检查，不能作时间基线。
